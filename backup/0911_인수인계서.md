1. 인수인계 목적
안전관리 플랫폼의 전체 업무 흐름은 다음과 같다.

작업관리대장
→ 위험성평가
→ 안전정보제공서
→ 수급인 확인·서명
→ 안전퀴즈
→ 안전작업허가서
→ TBM
→ 작업시작
→ 안전점검
→ 작업중지 또는 작업종료
→ 작업 리포트
이번 작업의 핵심 목적은 다음 세 가지다.

안전작업허가서 승인과 실제 작업시작 상태를 구분한다.
TBM을 승인된 안전작업허가서와 위험성평가의 정보를 승계하는 구조로 개선한다.
안전점검을 작업 연계 점검, 고위험작업 정기점검, 일반 안전점검으로 확장할 기반을 마련한다.

3. 대시보드 변경 및 검증 결과
3.1 기존 문제
기존 대시보드는 다음 조건으로 허가완료 작업을 작업중으로 집계했다.

status.code === 'approved'
이 때문에 TBM을 하지 않은 허가완료 작업도 모두 작업중으로 표시됐다.

향후 원칙

8. 모바일 프레임 관련
대시보드의 검은색 모바일 프레임은 다음 미디어쿼리에서만 표시된다.

@media(min-width:768px)
개발자도구를 오른쪽에 열면 실제 페이지 폭이 768px 미만으로 줄어든다.

이 경우:

모바일 CSS 적용
검은색 외곽 프레임 미표시
화면 전체 폭 사용
이는 정상 동작이며 CSS 오류가 아니다.

확인 기준:

console.log({
  width:window.innerWidth,
  desktop:
    matchMedia(
      '(min-width:768px)'
    ).matches
});
desktop: true → PC 프레임 표시
desktop: false → 모바일 레이아웃 표시
프레임 CSS는 수정하지 않는다.

현재 저장 구조에는 위험요인과 대책을 직접 연결하는 공통 ID가 없다.

안전대책 8~10건

• 설비 불시 기동
• 회전체와 끼임점
• 잔류에너지

• 방호덮개 확인

37. 다음 담당자에게 전달할 핵심 문장
현재 대시보드는 허가완료와 작업중을 분리했습니다.

허가완료 후 TBM 미완료 작업은 작업전 / TBM 대기로 표시하며, TBM을 완료한 작업만 작업중으로 표시합니다.

2026년 9월 10일 기준 검증 결과는 작업전 17건, TBM 대기 17건, 작업중 0건이었으며 작업전 목록의 카드 17건이 정상 표시됐습니다.

2026년 9월 11일 화면 기준 당일 작업은 13건입니다.

TBM은 위험성평가 원본을 다시 검색하지 않고, 승인된 안전작업허가서의 riskSnapshot을 기준으로 위험요인과 안전대책을 승계하도록 개편합니다.

위험요인과 안전대책은 저장 구조상 1:1 관계가 없으므로 별도 목록으로 표시해야 합니다.

TBM 서명은 작업중지권 고지 이후 당사 작업담당자, 작업책임자, 실제 작업자 전원이 진행합니다.

TBM 완료 후 허가서 상태를 inProgress로 변경하고, 대시보드에서는 작업중으로 표시합니다.

안전점검은 향후 작업 연계 점검, 고위험작업 정기점검, 일반 안전점검으로 구분합니다.

고위험작업은 전담 생명지킴이 2시간마다, 정비부서 담당자·운영부서 관리감독자·안전환경부서는 오전·오후 각 1회 점검하며 예정시각과 실제 점검시각을 모두 기록해야 합니다.

다음 수정 전에는 반드시 정상 파일을 백업하고, 단일 기능·단일 커밋·문법 검사·회귀 테스트 원칙을 지켜야 합니다.
