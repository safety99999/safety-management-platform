6. 위험성평가 사전 판정
6.1 개선된 흐름
기존에는 안전정보제공서 3단계에서 위험성평가 미연계를 발견해 사용자가 다시 돌아가야 했습니다.

현재는 대시보드의 복수 작업 선택 시 먼저 확인합니다.

✅ RA-20260909-002
⚠️ 위험성평가 미연계
➖ 위험성평가 해당 없음
6.2 선택 정책
각 작업은 다음 중 하나로 확정되어야 합니다.

완료된 위험성평가 자동 연계
위험성평가 해당 없음
해당 없음 사유는 선택사항
해당 없음은 사용자가 직접 선택
시스템이 자동으로 해당 없음을 판단하지 않음
상태 미결정 작업은 안전정보제공서 선택 불가
6.3 해당 없음 저장 키
localStorage.riskAssessmentExemptions
예:

{
  workId: '2026-09-09_2',
  applicability: 'notApplicable',
  status: 'notApplicable',
  reason: '',
  confirmedAt: '',
  confirmedBy: '',
  environment: 'test'
}
6.4 선택 복원
위험성평가 화면으로 이동하기 전에 현재 작업 선택을 저장합니다.

sessionStorage.pendingSafetyInfoSelection
유효시간은 2시간으로 구성했습니다.

하지만 신규 설계에 필요한 다음 컬렉션 규칙은 아직 없습니다.

test_publicSafetyProvisions
따라서 현재 상태에서는 해당 컬렉션에 저장하거나 외부 수급인이 조회하려고 하면 다음 오류가 발생합니다.

Missing or insufficient permissions
13.1 추가해야 할 Rules
현재 Rules에서 test_safetyProvisions 블록 다음에 추가하는 것을 권장합니다.

    /*
     * 수급인 공유용 안전정보제공서
     *
     * shareToken을 문서 ID로 사용합니다.
     * 외부 수급인은 단건 조회만 허용하며,
     * 목록 조회와 브라우저 직접 쓰기는 차단합니다.
     */
    match /test_publicSafetyProvisions/{shareToken} {
      allow get: if true;
      allow list: if false;

      allow create, update: if isActiveMember();
      allow delete: if isAdmin();
    }
전체 Rules를 이 블록만으로 덮어쓰면 안 됩니다. 기존의 아래 범위 안에 삽입해야 합니다.

service cloud.firestore {
  match /databases/{database}/documents {
    // 여기에 추가
  }
}
13.2 보안상 중요 사항
allow get: if true는 토큰을 알고 있는 외부인이 해당 문서를 읽을 수 있다는 의미입니다.

따라서 공개본에는 다음 자료를 넣지 않는 것이 좋습니다.

내부 승인 이력
관리자 UID
불필요한 개인 연락처
운영상 민감한 설비 상세정보
원본 서명 이미지
내부 메모
전체 사용자 목록
다른 문서 조회에 사용할 수 있는 식별정보
공개본은 수급인 확인에 필요한 최소 정보만 포함해야 합니다.

Missing or insufficient permissions
운영에서는 다음 중 하나가 필요합니다.

Cloud Functions
Google Apps Script 검증 API
Firebase 익명 인증
토큰 검증 가능한 서버 API
공개 컬렉션에 무조건 쓰기 권한을 주면 문서 위·변조 위험이 있으므로 권장하지 않습니다.

17.2 서명 이미지
서명 이미지를 Firestore 공개 문서에 직접 저장하지 않는 것을 권장합니다.

방식을 검토해야 합니다.

17.3 GitHub Pages 보안
공개 GitHub 저장소의 정적 자료는 외부 접근이 가능합니다.

공장 배치도와 상세 위치자료는 대외 제공 승인 후 업로드해야 합니다.

17.4 테스터와 인증 사용자
