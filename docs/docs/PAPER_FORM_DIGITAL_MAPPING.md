## 1. 문서 목적

이 문서는 기존 종이 안전서식의 항목과 전자 안전관리 플랫폼의 화면, 데이터, 승인 절차를 연결하기 위한 기준 문서이다.

전자화 과정에서 다음 문제가 발생하지 않도록 하는 것을 목적으로 한다.

- 종이 서식의 필수항목 누락
- 작성자·확인자·허가자 역할 혼동
- 위험성평가와 허가서의 정보 불일치
- 허가서와 TBM의 정보 불일치
- ILS 상세 시스템과 안전관리 플랫폼의 중복 관리
- 작업중지권 고지와 실제 작업중지 요청의 혼동
- 작업 중 점검기록 누락
- 작업 종료 전 ILS 잠금 해제
- 안전퀴즈 미합격자의 작업 참여
- 종이 문서와 전자 기록의 이중 작성
- 감사 및 출처 추적 불가

전자 시스템은 종이 서식의 단순 복사본이 아니라 다음 기능을 수행해야 한다.

- 필수항목 검증
- 앱 간 자동 채움
- 상태 전환 통제
- 작업별 조건부 항목 표시
- 위험성평가 결과의 허가서·TBM 연계
- 작업중지·조치·재개 이력 관리
- 작업 종료 및 ILS 해제 확인
- 관련 문서 통합 조회

## 2. 적용 원칙

### 2.1 종이 서식과 전자화의 관계

종이 서식의 항목은 다음 기준으로 전자화한다.

1. 법령·사내기준상 필수항목은 삭제하지 않는다.
2. 같은 정보를 여러 문서에서 반복 입력하지 않는다.
3. 최초 작성 앱의 데이터를 다른 앱이 조회하여 사용한다.
4. 자동 채움 데이터는 출처를 표시한다.
5. 자동 채움 데이터가 수정되면 수정자와 수정시각을 기록한다.
6. 조건부 항목은 해당 작업에만 표시한다.
7. 해당 없음 선택 시 사유를 기록한다.
8. 필수 안전조치가 미흡하면 다음 단계 진행을 제한한다.
9. AI 제안은 원문·법령·사내기준과 구분한다.
10. 전자 기록의 최종 확정은 권한 있는 사람이 수행한다.

### 2.2 중심 식별번호

문서 연결에는 다음 식별번호를 사용한다.

| 구분 | 식별번호 |
|---|---|
| 원본 작업 | workId |
| 안전정보제공서 | safeinfoNo |
| 안전퀴즈 | quizId |
| 위험성평가 | riskId |
| 안전작업허가서 | permitNo |
| TBM | tbmNo |
| 작업중지 요청 | emergencyNo |
| JSA_DB | jsaId |
| 작업 중 점검 | inspectionNo |

통합 리포트의 중심 식별번호는 원칙적으로 permitNo를 사용한다.

작업허가서 생성 전 단계에서는 workId를 사용한다.

### 2.3 감사 필드

모든 전자 문서에는 다음 감사 필드를 둔다.

- createdAt
- createdBy
- updatedAt
- updatedBy
- schemaVersion

승인·확인·서명·상태 변경에는 별도의 담당자와 시각을 기록한다.

### 2.4 작성 주체 구분

종이 서식의 작성 주체는 전자 시스템에서 다음 역할로 구분한다.

| 역할 | 주요 책임 |
|---|---|
| 작업지시자 | 작업지시, W/O, 작업범위 및 기본 안전정보 제공 |
| 작업수행사 작업책임자 | 작업방법, 작업자, 현장 안전조치 및 TBM 관리 |
| 운영부서 허가자 | 작업조건, 설비상태, ILS 상태 및 최종 허가 확인 |
| 안전관리자 | 고위험작업 검토, 현장점검, 기준 및 이행상태 확인 |
| 작업자 | 안전교육·퀴즈, TBM 참석, 개인 안전조치 및 작업중지권 행사 |
| 생명지킴이 | 고위험작업 현장 주기점검 |
| 지정 측정·평가자 | 밀폐공간 산소·유해가스 측정 및 기록 |
| 재개 승인자 | 작업중지 원인 조치 후 작업 재개 승인 |

## 3. 전체 전자 업무 흐름

전자 시스템의 기본 흐름은 다음과 같다.

1. 작업정보 등록
2. 도급인 안전정보제공서 발행
3. 수급인 안전정보 확인·서명
4. 출입자 안전퀴즈 응시·합격
5. 작업 위험성평가
6. 고위험작업 여부 판정
7. 고위험작업 맞춤 체크리스트 작성
8. 필요한 경우 담당 임원 또는 실장 사전승인
9. 안전작업허가 신청
10. 허가자가 필수 안전조치 확인
11. ILS 대상이면 기존 ILS 시스템의 완료상태 확인
12. 밀폐공간이면 최초 산소·유해가스 측정 및 확인
13. 최종 작업허가
14. TBM 실시
15. 위험요인·안전대책·조치예정자 전달
16. 참석자의 안전퀴즈 합격 여부 확인
17. 작업중지권 고지 및 서명
18. 필요한 별지 확인
19. 작업 시작
20. 작업 중 안전조치 이행점검
21. 위험 발견 시 작업중지
22. 개선조치·재평가·허가 재확인·재TBM
23. 작업 종료
24. 작업자·공구·자재 철수
25. 방호장치 및 설비 복구
26. 기존 ILS 시스템에서 잠금 해제
27. 허가서에서 ILS 해제 완료 확인
28. 설비 인계 및 재가동 승인
29. 작업완료 처리
30. 통합 리포트 및 기록 보관

## 5. 안전정보제공서 도급인용 매핑

### 5.1 목적

도급인이 수급인에게 작업장 및 작업 관련 위험정보를 제공하고, 수급인이 작업 전 이를 확인할 수 있도록 한다.

### 5.2 종이·업무 항목과 전자 필드

| 종이·업무 항목 | 전자 필드 예시 | 필수 | 작성 주체 | 연계 대상 |
|---|---|:---:|---|---|
| 안전정보제공서 번호 | safeinfoNo | 필수 | 시스템 | 전체 |
| 작업 ID | workId | 조건부 | 시스템 | 작업DB |
| 허가서 번호 | permitNo | 조건부 | 시스템 | 작업허가 |
| 작업명 | workName | 필수 | 도급인 | 위험성평가·허가서 |
| 작업장소 | location, detailLocation | 필수 | 도급인 | 위험성평가·TBM |
| 작업기간 | startDateTime, endDateTime | 필수 | 도급인 | 허가서 |
| 도급인 정보 | employer | 필수 | 도급인 | 수급인용 |
| 수급인 정보 | contractor | 필수 | 도급인 | 수급인용 |
| 위험설비 | hazardousEquipment | 조건부 | 도급인 | 위험성평가 |

| 필수 보호구 | requiredPPE | 조건부 | 도급인 | 허가서·TBM |
| 비상연락망 | emergencyContacts | 필수 | 도급인 | TBM |
| 비상구·AED·구급함 | emergencyFacilities | 필수 | 도급인 | TBM |
| 필요 서류 | requiredDocuments | 조건부 | 도급인 | 허가서 |
| 작성자 확인 | issuer | 필수 | 도급인 | 감사 |
| 발행시각 | issuedAt | 필수 | 시스템 | 감사 |
| 상태 | status | 필수 | 시스템 | 대시보드 |

### 5.3 상태

- 발행완료
- 서명완료
- 반려

### 5.4 위험성평가 연계

다음 항목을 위험성평가 입력자료로 사용한다.

- 작업장 고유 위험
- 위험설비
- 화학물질 및 MSDS
- 작업 제한사항
- 필수 보호구
- 비상정보

위 정보는 `도급인 제공정보` 출처로 표시한다.

## 6. 안전정보제공서 수급인용 매핑

### 6.1 목적

수급인이 도급인이 제공한 안전정보를 확인하고, 작업내용과 현장조건의 일치 여부를 검토하도록 한다.

### 6.2 전자화 항목

| 항목 | 전자 필드 예시 | 필수 |
|---|---|:---:|
| 안전정보제공서 번호 | safeinfoNo | 필수 |
| 도급인 원문 조회 | employerInformation | 필수 |
| 작업내용 일치 여부 | workInfoMatched | 필수 |
| 작업장소 일치 여부 | locationMatched | 필수 |
| 제공정보 충분 여부 | informationSufficient | 필수 |
| MSDS 확인 | msdsConfirmed | 조건부 |
| 추가 정보 요청 | additionalRequest | 조건부 |
| 반려 사유 | rejectionReason | 조건부 |
| 수급인 담당자 | contractorSigner | 필수 |
| 수급인 서명 | contractorSignature | 필수 |
| 확인시각 | signedAt | 필수 |
| 상태 | status | 필수 |

### 6.3 허가 진행 조건

필수 안전정보제공 대상 작업은 다음 조건을 충족해야 허가 절차를 진행할 수 있다.

- 도급인 발행 완료
- 수급인 확인·서명 완료
- 반려상태가 아님
- 작업명·업체·장소 일치
- 필요한 MSDS 확인
- 추가 요청사항 처리 완료

## 7. 안전퀴즈 매핑

### 7.1 운영 원칙

안전퀴즈 합격은 작업현장 출입 및 작업 참여의 필수조건으로 관리한다.

다음 대상은 유효한 합격 기록이 있어야 한다.

- 직접 작업자
- 작업책임자
- 관계수급사 참여자
- 작업 지원 인원
- 사내기준상 퀴즈가 필요한 출입자

방문자·감독자 등 예외 대상은 사내 출입기준에 따라 별도로 정의한다.

### 7.2 전자화 항목

| 항목 | 전자 필드 예시 | 필수 |
|---|---|:---:|
| 퀴즈 ID | quizId | 필수 |
| 응시자 식별값 | respondentId | 권장 |
| 응시자 이름 | respondent | 필수 |
| 소속 회사 | respondentCompany | 필수 |
| 응시일 | date | 필수 |
| 응시시각 | startedAt, completedAt | 필수 |
| 문항 버전 | quizVersion | 필수 |
| 총 문항수 | totalQuestions | 필수 |
| 정답수 | correctAnswers | 필수 |
| 점수 | score | 필수 |
| 결과 | status | 필수 |
| 유효 시작일 | validFrom | 권장 |
| 유효 종료일 | validUntil | 필수 |
| 재응시 횟수 | attemptNo | 권장 |
| 확인 또는 서명 | acknowledgement | 조건부 |
| 감사 필드 | createdAt, createdBy 등 | 필수 |

status 허용값:

- 합격
- 불합격

### 7.3 출입 검증

TBM 참석자 또는 작업 참여자마다 다음을 검증한다.

- 퀴즈 응시 여부
- 합격 여부
- 유효기간
- 퀴즈 버전
- 이름 또는 식별값 일치
- 소속 회사 일치

검증 결과:

| 결과 | 처리 |
|---|---|
| 합격·유효 | 출입 및 작업 참여 가능 |
| 불합격 | 출입 및 작업 참여 제한 |
| 미응시 | 응시 완료 전 참여 제한 |
| 기간 만료 | 재응시 필요 |
| 신원·소속 불일치 | 관리자 확인 필요 |

필수 대상자 중 한 명이라도 조건을 충족하지 못하면 TBM 최종 완료와 작업 시작을 제한한다.

### 7.4 작업중지 신고 예외

안전퀴즈 미응시자 또는 불합격자라도 위험상황 신고와 작업중지 요청을 차단하지 않는다.

작업 참여 자격과 위험 신고 권리는 분리한다.

## 8. 위험성평가 매핑

### 8.1 목적

위험성평가는 현재 작업조건에 따라 위험요인을 발굴하고, 위험별 안전대책과 최초·잔여 위험도를 평가한다.

JSA_DB는 위험성평가를 지원하지만 최종 평가를 자동 확정하지 않는다.

### 8.2 기본정보

| 종이·업무 항목 | 전자 필드 예시 | 필수 |
|---|---|:---:|
| 평가번호 | riskId | 필수 |
| 작업 ID | workId | 조건부 |
| 허가서 번호 | permitNo | 조건부 |
| 작업명 | workName | 필수 |
| 작업장소 | location, detailLocation | 필수 |
| 작업유형 | primaryWorkType | 필수 |
| 복수 작업유형 | workTypes | 권장 |
| 작업단계 | workStages | 필수 |
| 작업 상세내용 | workDesc | 필수 |
| 사용장비·공구 | equipment | 조건부 |

## 10. 허가 전 필수 조치 매핑

- 안전관리자 또는 담당부서 확인

### 10.2 ILS 적용 원칙

이 플랫폼은 별도 ILS 시스템을 대체하지 않는다.

기존 ILS 시스템이 다음 상세정보의 원본 시스템이다.

- 차단점
- 잠금자
- 확인자
- 개인잠금
- GIB
- 잠금키
- 잠금 해제
- 복전 절차

안전관리 플랫폼은 다음 정보만 확인·기록한다.

- ILS 적용 대상 여부
- 실시 상태
- 기존 ILS 시스템 참조번호
- 기계설비 ILS 상태
- 전기설비 ILS 상태
- GIB 번호
- 허가 전 확인자
- 허가 전 확인시각
- 비대상 사유
- 가동 Test·미세조정 여부

### 10.3 허가 전 ILS 차단 조건

ILS 적용 대상 작업은 다음 조건을 충족하지 못하면 허가완료로 전환할 수 없다.

- ILS 완료상태 확인
- 참조번호 확인
- 대상 설비 일치
- 확인자 기록
- 확인시각 기록
- 특수절차 대상이면 승인 근거 확인

### 10.4 허가 전 확인 문구

허가자는 다음 취지의 확인을 수행한다.

> 해당 작업에 필요한 ILS가 기존 ILS 시스템에서 완료되었으며, 작업 대상 설비 및 작업범위와 일치함을 확인하였습니다.

## 2. 적용 원칙

### 2.1 종이 서식과 전자화의 관계

종이 서식의 항목은 다음 기준으로 전자화한다.

1. 법령·사내기준상 필수항목은 삭제하지 않는다.
2. 같은 정보를 여러 문서에서 반복 입력하지 않는다.
3. 최초 작성 앱의 데이터를 다른 앱이 조회하여 사용한다.
4. 자동 채움 데이터는 출처를 표시한다.
5. 자동 채움 데이터가 수정되면 수정자와 수정시각을 기록한다.
6. 조건부 항목은 해당 작업에만 표시한다.
7. 해당 없음 선택 시 사유를 기록한다.
8. 필수 안전조치가 미흡하면 다음 단계 진행을 제한한다.
9. AI 제안은 원문·법령·사내기준과 구분한다.
10. 전자 기록의 최종 확정은 권한 있는 사람이 수행한다.

- 불합격

### 7.3 출입 검증

TBM 참석자 또는 작업 참여자마다 다음을 검증한다.

- 퀴즈 응시 여부
- 합격 여부
- 유효기간
- 퀴즈 버전
- 이름 또는 식별값 일치
- 소속 회사 일치

검증 결과:

| 결과 | 처리 |
|---|---|
| 합격·유효 | 출입 및 작업 참여 가능 |
| 불합격 | 출입 및 작업 참여 제한 |
| 미응시 | 응시 완료 전 참여 제한 |
| 기간 만료 | 재응시 필요 |
| 신원·소속 불일치 | 관리자 확인 필요 |

필수 대상자 중 한 명이라도 조건을 충족하지 못하면 TBM 최종 완료와 작업 시작을 제한한다.

### 7.4 작업중지 신고 예외

안전퀴즈 미응시자 또는 불합격자라도 위험상황 신고와 작업중지 요청을 차단하지 않는다.

작업 참여 자격과 위험 신고 권리는 분리한다.

## 8. 위험성평가 매핑

### 8.1 목적

위험성평가는 현재 작업조건에 따라 위험요인을 발굴하고, 위험별 안전대책과 최초·잔여 위험도를 평가한다.

JSA_DB는 위험성평가를 지원하지만 최종 평가를 자동 확정하지 않는다.

### 8.2 기본정보

| 종이·업무 항목 | 전자 필드 예시 | 필수 |
|---|---|:---:|
| 평가번호 | riskId | 필수 |
| 작업 ID | workId | 조건부 |
| 허가서 번호 | permitNo | 조건부 |
| 작업명 | workName | 필수 |
| 작업장소 | location, detailLocation | 필수 |
| 작업유형 | primaryWorkType | 필수 |
| 복수 작업유형 | workTypes | 권장 |
| 작업단계 | workStages | 필수 |
| 작업 상세내용 | workDesc | 필수 |
| 사용장비·공구 | equipment | 조건부 |
| 물질·에너지원 | materials, energySources | 조건부 |
| 협력사 | company | 필수 |
| 작업인원 | workers | 조건부 |
| 평가자 | assessor | 필수 |
| 평가일 | date | 필수 |

### 8.3 위험요인별 평가

각 위험요인은 다음 구조로 관리한다.

| 항목 | 설명 |
|---|---|
| riskItemId | 평가 내 위험항목 식별번호 |
| hazardText | 위험요인 |
| hazardSource | 원문·JSA_DB·AI·사용자 |
| sourceJsaId | 참조 JSA |
| sourceHazardId | 참조 위험 ID |
| workStage | 관련 작업단계 |
| accidentTypes | 예상 사고유형 |
| scenario | 사고시나리오 |
| initialRisk | 대책 적용 전 위험도 |
| selectedMeasures | 선택한 안전대책 |
| residualRisk | 대책 적용 후 잔여 위험도 |
| controlAdequacy | 통제 적정성 |
| adequacyReason | 판정 사유 |
| unresolved | 미해결 위험 여부 |
| actionOwner | 조치 담당자 |
| dueDate | 조치 예정일 |

### 8.4 위험요인 출처

- 작업 원문
- 도급인 안전정보
- JSA_DB
- 사내기준
- 작업표준
- 재해사례
- 아차사고
- 외부기준
- AI
- 사용자 추가

AI가 제안한 위험은 원문 위험과 구분하고 기본 미선택 상태로 표시한다.

### 8.5 JSA_DB 참조

위험성평가는 복수 JSA를 참조할 수 있다.

참조정보에는 다음을 기록한다.

- jsaId
- classCode
- workName
- similarity
- 참조 버전
- 선택 위험 ID
- 선택 대책 ID
- 참조 시각

### 8.6 위험도

각 위험요인별로 다음을 구분한다.

- 최초 빈도
- 최초 강도
- 최초 점수
- 최초 위험등급
- 잔여 빈도
- 잔여 강도
- 잔여 점수
- 잔여 위험등급

전체 작업의 종합 위험도는 위험요인별 결과를 바탕으로 산정한다.

### 8.7 통제 적정성

허용값:

- ○
- △
- ×

시스템은 다음을 검토하여 추천값을 제시할 수 있다.

- 필수대책 누락
- PPE 중심 여부
- 상위 통제수단 포함 여부
- 위험요인과 대책의 연결 여부
- 미해결 위험 존재 여부

사용자가 시스템 추천과 다른 값을 확정하면 변경 사유를 기록한다.

### 8.8 고위험작업 판정

위험성평가 단계에서 다음 정보를 생성한다.

- highRiskApplicable
- highRiskCategories
- highRiskReasons
- exceptionApplied
- exceptionReason
- checklistRequired
- executiveApprovalRequired

고위험작업 판정기준은 HIGH_RISK_WORK_POLICY.md를 따른다.

- 기타 위험 특화 보호구

기본 보호구와 위험 특화 보호구를 구분한다.

위험성평가와 MSDS에서 선정한 보호구를 허가서에 자동 제안할 수 있으나, 현장 담당자가 최종 확인한다.

## 10. 허가 전 필수 조치 매핑

### 10.1 공통 확인

종이 양식의 허가 전 필수조치는 다음 영역으로 관리한다.

- ILS 상태
- 안전펜스·안전구역 설정
- 가스농도 측정
- 위험물질 제거·인화성가스 관리
- 작업계획서 및 관련 자료 준비
- 보호구 착용
- 점검 대상 장비 상태
- 안전관리자 또는 담당부서 확인

### 10.2 ILS 적용 원칙

이 플랫폼은 별도 ILS 시스템을 대체하지 않는다.

기존 ILS 시스템이 다음 상세정보의 원본 시스템이다.

- 차단점
- 잠금자
- 확인자
- 개인잠금
- GIB
- 잠금키
- 잠금 해제
- 복전 절차

안전관리 플랫폼은 다음 정보만 확인·기록한다.

- ILS 적용 대상 여부
- 실시 상태
- 기존 ILS 시스템 참조번호
- 기계설비 ILS 상태
- 전기설비 ILS 상태
- GIB 번호
- 허가 전 확인자
- 허가 전 확인시각
- 비대상 사유
- 가동 Test·미세조정 여부

### 10.3 허가 전 ILS 차단 조건

ILS 적용 대상 작업은 다음 조건을 충족하지 못하면 허가완료로 전환할 수 없다.

- ILS 완료상태 확인
- 참조번호 확인
- 대상 설비 일치
- 확인자 기록
- 확인시각 기록
- 특수절차 대상이면 승인 근거 확인

### 10.4 허가 전 확인 문구

허가자는 다음 취지의 확인을 수행한다.

> 해당 작업에 필요한 ILS가 기존 ILS 시스템에서 완료되었으며, 작업 대상 설비 및 작업범위와 일치함을 확인하였습니다.

## 11. 허가 승인 상태

작업자의 제출과 허가자의 최종 승인을 구분한다.

| 단계 | 권장 상태 |
|---|---|
| 작성 중 | 대기중 |
| 작업수행사 제출 | 허가진행중 |
| 작업책임자 확인 | 허가진행중 |
| 운영부서 허가자 승인 | 허가완료 |

| 위험 발생 | 작업중지 |
| 종료 절차 완료 | 작업완료 |

작업자가 서명했다는 이유만으로 허가완료 상태가 되면 안 된다.

최종 허가에는 최소한 다음을 기록한다.

- 허가자
- 허가자 소속
- 허가 시각
- 허가자 서명 또는 인증
- 필수 안전조치 확인결과
- ILS 완료 확인
- 밀폐공간 최초 측정 확인
- 고위험 사전승인 확인
- 허가 의견

## 12. 산소 및 유해가스 측정 매핑

### 12.1 적용 대상

다음 작업에는 산소 및 유해가스 측정 기록을 적용한다.

- 밀폐공간 작업
- 산소결핍 가능 작업
- 유해가스가 존재하거나 유입·발생할 수 있는 작업
- 인화성가스가 존재할 수 있는 장소의 화기작업
- 사내기준 또는 위험성평가에서 측정이 필요하다고 판단한 작업

밀폐공간 작업과 화기작업은 측정 목적과 판정기준이 다를 수 있으므로 구분하여 관리한다.

### 12.2 적정공기 기준

현재 확인된 밀폐공간 기준은 다음과 같다.

| 항목 | 적정 기준 | 부적합 조건 |
|---|---:|---:|
| 산소 O₂ | 18% 이상, 23.5% 미만 | 18% 미만 또는 23.5% 이상 |
| 일산화탄소 CO | 30ppm 미만 | 30ppm 이상 |
| 이산화탄소 CO₂ | 1.5% 미만 | 1.5% 이상 |
| 황화수소 H₂S | 10ppm 미만 | 10ppm 이상 |
| 인화성가스 LEL | 10% 미만 | 10% 이상 |

화기작업 자료에는 `LEL 0% 초과 시 작업중지` 기준이 별도로 제시되어 있다.

따라서 시스템은 다음 기준을 혼용하지 않는다.

- 밀폐공간 적정공기 판정기준
- 화기작업 실시 가능 판정기준
- 개별 물질·공정별 강화기준

화기작업 LEL 기준의 정확한 적용범위와 최신성은 사내 담당자의 최종 확인 후 적용한다.

### 12.3 측정 시기

밀폐공간 작업의 측정 시기는 다음과 같이 관리한다.

- 당일 작업 개시 전
- 작업자 전원 교대 후 작업 재개 전
- 작업장소를 떠났다가 다시 진입하기 전
- 작업자 신체 또는 환기장치 등에 이상이 있을 때
- 연속작업 중 1시간마다
- 사업장별 프로그램에 따라 측정 간격을 단축한 경우
- 작업중지 원인 조치 후 재진입 전

기본 측정주기는 1시간으로 관리한다.

30분 등 단축 주기를 적용하는 경우 다음을 기록한다.

- 단축 사유
- 적용 기준
- 승인자
- 적용 시작·종료 시각

### 12.4 최초 측정 확인

최초 측정은 원칙적으로 다음 관련자가 합동으로 확인한다.

- 작업수행사 관리감독자
- 운영부서 지정 측정·평가자
- 정비부서 담당자

운영부서가 직접 발주·수행하는 작업에 2자 확인을 적용하는 경우 다음을 기록한다.

- 직접 수행 여부
- 2자 확인 적용 사유
- 작업수행자 또는 관리감독자
- 운영부서 지정 측정·평가자

### 12.5 측정 위치

측정 위치는 한 개 지점으로 제한하지 않는다.

다음 위치를 작업공간의 형상과 위험 특성에 따라 기록한다.

- 수직방향 측정 위치
- 수평방향 측정 위치
- 상부
- 중부
- 하부
- 출입구
- 작업자 호흡 위치
- 가스 유입 예상 위치
- 작업지점
- 기타 상세 위치

사내기준에 따라 수직방향 및 수평방향 각각 3개소 이상의 측정 필요 여부를 확인한다.

### 12.6 측정 기록 필드

각 측정 건은 다음 정보를 가진다.

| 종이 양식 항목 | 전자 필드 예시 | 필수 |
|---|---|:---:|
| 측정 구분 | measurementType | 필수 |
| 측정 일시 | measuredAt | 필수 |
| 측정 장소 | location | 필수 |
| 상세 위치 | measurementPoint | 필수 |
| 위치 구분 | positionType | 권장 |
| 깊이·높이 | depthOrHeight | 조건부 |
| 호흡 위치 여부 | breathingZone | 조건부 |
| 산소 | oxygen | 필수 |
| 일산화탄소 | carbonMonoxide | 필수 |
| 이산화탄소 | carbonDioxide | 필수 |
| 황화수소 | hydrogenSulfide | 필수 |
| 인화성가스 | lel | 필수 |
| 측정자 | measuredBy | 필수 |
| 측정자 소속 | measuredByDepartment | 필수 |
| 교육 이수 여부 | trainedEvaluator | 필수 |
| 측정기 식별정보 | instrument | 권장 |
| 판정 | result | 필수 |
| 후속조치 | correctiveAction | 조건부 |
| 재측정 필요 여부 | remeasurementRequired | 필수 |

measurementType 예:

- 최초
- 작업중
- 교대전
- 재진입전
- 이상발생
- 작업재개전

### 12.7 판정 및 차단 원칙

다음 조건에서는 작업 시작 또는 계속 수행을 제한한다.

- 필수 측정값 누락
- 측정자 정보 누락
- 필수 확인자 누락
- 측정 위치 부족
- 측정기 이상
- 산소 농도 부적합
- 유해가스 농도 부적합
- 인화성가스 기준 초과
- 후속조치 미완료
- 재측정 필요 상태
- 측정주기 초과

한 위치라도 부적합하면 전체 작업조건을 재검토한다.

산소는 위치별 최저값과 최고값을 모두 확인하고, 유해가스는 위치별 최고값을 중심으로 확인하는 방향을 검토한다. 최종 판정방식은 사내 담당자가 확정한다.

### 12.8 기록 보존

산소 및 유해가스 측정기록은 다음 정보를 포함하여 사내기준상 필요한 기간 동안 보존한다.

- 측정자 성명
- 측정 일시
- 측정 장소
- 측정 결과
- 평가 결과
- 후속조치
- 재측정 결과

현재 확보된 기준에는 3년 보존이 명시되어 있으므로 정식 운영 시 localStorage만을 법정·사내 보존수단으로 사용하지 않는다.

## 13. 고위험작업 판정 및 사전승인 매핑

### 13.1 고위험작업의 의미

고위험작업은 화기, 밀폐공간, 고부식성 유해화학물질, 고위험 고소·중량물·전기작업 등 중대재해가 발생할 가능성이 높은 작업을 의미한다.

작업유형과 고위험 특별관리 대상 여부를 구분한다.

예:

- 작업유형: 화기작업
- 고위험 특별관리: 해당
- 판정 사유: 인화성가스 존재 장소에서 화기작업

### 13.2 고위험 판정 필드

| 항목 | 전자 필드 예시 |
|---|---|
| 고위험 해당 여부 | highRisk.applicable |
| 고위험 분류 | highRisk.categories |
| 판정 사유 | highRisk.reasons |
| 판정 기준 | highRisk.criteria |
| 예외 적용 여부 | highRisk.exceptionApplied |
| 예외 내용 | highRisk.exceptionReason |
| 판정자 | highRisk.assessedBy |
| 판정 시각 | highRisk.assessedAt |
| 맞춤 체크리스트 필요 여부 | highRisk.checklistRequired |
| 임원·실장 승인 필요 여부 | highRisk.executiveApprovalRequired |

### 13.3 고위험작업 분류

최소한 다음 분류를 지원한다.

- 화재·폭발 위험개소 작업
- 밀폐공간 작업
- 고부식성 강산·강염기 작업
- 고소작업
- 중량물·양중작업
- 고위험 전기작업

세부 적용조건과 예외사항은 HIGH_RISK_WORK_POLICY.md를 따른다.

### 13.4 사전승인

고위험작업은 다음 자료를 첨부하여 권한 있는 담당자의 사전승인을 받는다.

- 작업계획
- 위험성평가
- 맞춤 체크리스트
- 생명지킴이 배치계획
- ILS 계획 또는 완료 확인
- 작업별 필수자료
- 예외 적용 근거

사전승인 기록에는 다음을 포함한다.

- 승인 필요 여부
- 승인 상태
- 승인자
- 승인자 직책
- 승인 시각
- 승인 의견
- 반려 사유
- 첨부자료 확인 결과

고위험 사전승인이 필요한 작업은 승인 완료 전까지 최종 작업허가를 제한한다.

## 14. 작업별 안전조치 체크리스트 매핑

### 14.1 체크리스트 구성 원칙

전자 체크리스트는 다음 자료를 결합하여 생성한다.

1. 종이 허가서 공통항목
2. 작업유형별 사내기준
3. 위험성평가에서 선택한 안전대책
4. 고위험작업 필수항목
5. 재해·아차사고 재발방지 항목
6. 현장 추가항목

고정된 모든 문항을 모든 작업에 표시하지 않는다.

사용자가 선택한 작업유형, 설비, 장비, 물질 및 위험요인에 따라 필요한 항목만 표시한다.

### 14.2 체크리스트 항목 구조

각 체크리스트 항목에는 다음 정보를 둔다.

- itemId
- 항목명
- 상세 설명
- 적용 작업유형
- 관련 위험요인
- 관련 안전대책
- 출처
- 필수 여부
- 판정
- 해당 없음 사유
- 점검자
- 점검시각
- 미흡사항
- 조치 담당자
- 조치결과
- 재점검 결과

### 14.3 판정값

종이 양식과의 호환을 위해 다음 값을 기본으로 사용한다.

- ○: 양호
- ×: 미흡
- -: 해당 없음

해당 없음에는 사유를 기록한다.

사내기준상 반드시 확인해야 하는 필수항목은 해당 없음 선택을 제한하거나 별도 승인하도록 한다.

### 14.4 작업유형 분리

최소한 다음 유형별 체크리스트를 구분한다.

- 일반작업
- 화기작업
- 밀폐공간
- 전기 정전작업
- 전기 충전작업
- 고소작업
- 양중·중량물
- 중장비·하역
- 굴착작업
- 화학물질
- 방사선·관리구역
- 작업장비

`중량물·유해가스` 또는 `밀폐공간·굴착·기타`처럼 서로 다른 위험군을 하나의 데이터 코드로 합치지 않는다.

## 15. TBM 전용 문서 매핑

### 15.1 파일 분리 원칙

TBM과 실제 작업중지 요청은 별도 파일로 분리한다.

권장 파일:

- TBM: `TBM_v2.html`
- 작업중지 요청: `작업중지권_v2.html`

기존 `TBM_및_작업중지권_v2.html`은 신규 파일 검증이 끝날 때까지 유지한다.

### 15.2 TBM의 역할

TBM은 다음 기능을 담당한다.

- 허가서 기본정보 확인
- 위험성평가 결과 확인
- 잠재 위험요인 전달
- 사고시나리오 전달
- 안전대책 전달
- 조치 예정자 지정
- ILS 완료상태 확인
- 참석자 안전퀴즈 검증
- 작업중지권 고지
- 참석자 확인·서명
- 조건부 별지 연결
- 재TBM 이력 관리

실제 작업중지 요청·개선조치·재개승인은 작업중지권 전용 앱에서 관리한다.

### 15.3 기본정보

| 종이 양식 항목 | 전자 필드 예시 | 필수 |
|---|---|:---:|
| TBM 번호 | tbmNo | 필수 |
| 허가서 번호 | permitNo | 필수 |
| 위험성평가 번호 | riskId | 조건부 |
| 작업 ID | workId | 필수 |
| 작업명 | workName | 필수 |
| 작업장소 | location | 필수 |
| 작업회사·부서 | company | 필수 |
| 작업인원 | workerCount | 필수 |
| 실시 일시 | conductedAt | 필수 |
| 실시자 | conductedBy | 필수 |
| 작업책임자 | supervisor | 필수 |
| 119 출동지점 | emergencyDispatchPoint | 조건부 |

TBM에는 작업 시작·종료시간을 별도로 중복 관리하지 않는다.

작업시간은 안전작업허가서를 원본으로 사용한다.

### 15.4 위험요인·대책·조치자

종이 TBM의 다음 구조를 유지한다.

| 잠재 위험요인 | 대책·안전조치사항 | 조치 예정자 |
|---|---|---|

전자 데이터에서는 각 행에 다음 정보를 추가한다.

- hazardId
- 위험요인
- 사고시나리오
- 안전대책
- 조치 예정자
- 확인방법
- 관련 riskItemId
- 관련 jsaId
- 자동 채움 출처
- 이행 확인 상태

위험성평가에서 가져온 위험과 대책을 연결된 한 묶음으로 전달한다.

대책 문자열만 전달하고 위험요인을 `위험성평가에서 도출`로 일괄 표시하지 않는다.

### 15.5 자동 채움

TBM은 URL의 permitNo를 기준으로 허가서를 조회한다.

허가서에서 다음 정보를 자동 채운다.

- 작업명
- 작업장소
- 협력사
- 작업인원
- 작업책임자
- 작업유형
- 밀폐공간 여부
- ILS 상태
- 위험성평가 번호

위험성평가에서는 다음 정보를 가져온다.

- 선택된 위험요인
- 사고시나리오
- 승인된 안전대책
- 대책 담당자
- 확인방법
- 통제 적정성
- 참조 JSA

자동 채움된 정보는 사용자가 식별할 수 있도록 표시한다.

사용자가 수정하면 자동 채움 표시를 해제하고 수정이력을 기록한다.

### 15.6 중복 방지

동일한 permitNo와 riskItemId 또는 hazardId를 기준으로 중복을 방지한다.

위험성평가가 변경되어도 기존 TBM을 자동으로 덮어쓰지 않는다.

사용자가 `최신 위험성평가 다시 불러오기`를 실행한 경우에만 갱신한다.

갱신 시 다음을 기록한다.

- 이전 riskId
- 신규 riskId
- 갱신자
- 갱신 시각
- 변경된 위험
- 변경된 대책
- 재TBM 필요 여부

## 16. TBM 참석자와 안전퀴즈 검증

### 16.1 필수조건

작업현장 출입과 작업 참여가 필요한 TBM 참석자는 유효한 안전퀴즈 합격 기록이 있어야 한다.

각 참석자별로 다음을 확인한다.

- 참석자 식별값
- 이름
- 소속
- 퀴즈 합격 여부
- 응시일
- 유효 종료일
- 퀴즈 버전
- 검증 결과

### 16.2 검증 결과

| 검증 결과 | 처리 |
|---|---|
| 합격·유효 | 참석 및 작업 참여 가능 |
| 불합격 | 작업 참여 제한 |
| 미응시 | 퀴즈 응시 후 참여 |
| 유효기간 만료 | 재응시 필요 |
| 소속 불일치 | 관리자 확인 |
| 식별 불가 | 작업 참여 제한 또는 확인 절차 |

필수 대상자 중 조건을 충족하지 못한 사람이 있으면 TBM 최종 완료와 작업 시작을 제한한다.

### 16.3 위험 신고 예외

퀴즈 결과와 관계없이 누구나 위험을 알리고 작업중지를 요청할 수 있어야 한다.

안전퀴즈는 작업 참여 조건이며 작업중지 신고 권리를 제한하는 조건이 아니다.

## 17. TBM의 ILS 확인

### 17.1 역할

TBM은 기존 ILS 시스템의 상세 잠금정보를 입력하거나 수정하지 않는다.

허가서에서 확인한 ILS 상태를 읽기 전용으로 표시하고 참석자가 확인하도록 한다.

### 17.2 표시 항목

- ILS 적용 여부
- ILS 완료 상태
- 기계설비 ILS 참조번호
- 전기설비 ILS 참조번호
- GIB 번호
- 허가 전 확인자
- 확인 시각
- 기존 ILS 시스템 확인 여부

### 17.3 확인 문구

> 안전작업허가서에서 확인된 ILS 실시 상태와 참조번호를 확인하였으며, 작업 중 잠금장치의 임의 해제·변경·바이패스 및 설비 조작을 하지 않겠습니다.

### 17.4 작업 시작 제한

다음 조건에서는 TBM 완료와 작업 시작을 제한한다.

- ILS 대상인데 완료되지 않음
- ILS 참조번호가 없음
- 허가서와 대상 설비가 다름
- ILS 상태가 변경됨
- 기존 ILS 시스템의 완료상태를 확인할 수 없음

## 18. TBM 작업중지권 고지

### 18.1 TBM에 남길 기능

TBM에는 작업중지권의 사전 고지와 확인 기능을 유지한다.

고지 내용에는 다음 취지를 포함한다.

- 급박한 위험이 있으면 작업을 중지하고 대피할 수 있음
- 위험상황을 관리감독자에게 보고
- 필요한 안전조치 후 작업 재개
- 합리적인 작업중지권 행사에 대한 불이익 금지
- 실제 작업중지 요청 방법

### 18.2 stopNotice 구조

TBM에는 다음 정보를 저장한다.

- 참여자 명단
- 참여자 원문
- 대표자 이름
- 대표자 서명
- 고지 시각
- 법적 근거
- 고지 문구 버전
- 확인 결과

### 18.3 필수 검증

TBM 완료 시 다음 항목을 확인한다.

- 참여자 명단 존재
- 대표자 이름 존재
- 대표자 서명 존재
- 고지 시각 존재
- 고지 문구 버전 존재

### 18.4 작업중지권 앱 연결

TBM에는 다음과 같이 명확한 버튼을 제공한다.

- `위험 발견·작업중지 요청`

버튼은 작업중지권 전용 앱으로 이동하며 permitNo와 필요 시 tbmNo만 전달한다.

### 50.1 모든 허가작업의 최초 이행상태 확인

모든 허가 대상 작업은 고위험작업 해당 여부와 관계없이 작업 시작 후 3시간 이내에 작업 중 안전 이행상태를 확인한다.

기본 확인 주체는 작업수행사 관리감독자이다.

다음 정보를 기록한다.

- 작업수행사 관리감독자 소속
- 작업수행사 관리감독자 직책
- 작업수행사 관리감독자 성명
- 실제 작업 시작시각
- 점검 예정기한
- 실제 확인시각
- 허가조건 이행 여부
- 위험성평가 대책 이행 여부
- 작업방법 변경 여부
- 작업인원 변경 여부
- 설비·장비·공구 변경 여부
- 사용물질·에너지원 변경 여부
- 보호구 착용상태
- 작업구역 통제상태
- ILS 상태 유지 여부
- 신규 위험요인 발생 여부
- 작업중지 조건 발생 여부
- 점검 의견 또는 Audit 결과
- 미흡사항 및 조치결과

점검 예정기한은 허가서에 기록된 실제 작업 시작시각을 기준으로 계산한다.

점검이 3시간 이내에 이루어지지 않으면 다음과 같이 처리한다.

- 대시보드에 `점검지연` 경고 표시
- 허가서에 미점검 상태 표시
- 작업수행사 관리감독자에게 확인 요구
- 점검 완료 전 작업 지속 가능 여부를 현장 책임자가 검토
- 지연 사유와 실제 점검시각 기록

3시간 경과만으로 자동 작업중지 처리할지는 사내 운영기준을 확인한 후 확정한다.

작업시간이 3시간 이내인 단시간 작업의 점검 시점과 예외 여부는 사내기준 확인 전까지 자동 면제하지 않는다.

### 50.2 Audit 부서 확인

종이 허가서에는 Audit 부서의 이행상태 확인란이 있으므로 다음 정보를 기록할 수 있어야 한다.

- Audit 부서 소속
- 직책
- 성명
- 확인시각
- 의견 또는 Audit 결과
- 미흡사항
- 조치 요구
- 재점검 결과

현재 확보된 자료에서는 작업 시작 후 3시간 이내 확인 의무가 작업수행사 관리감독자에게 명시되어 있다.

Audit 부서의 필수 확인 여부와 확인 주기는 별도 사내기준이 확인되기 전까지 조건부로 관리한다.

### 50.3 일반 작업의 추가 확인

최초 3시간 이내 확인 이후에도 다음 상황이 발생하면 추가 점검한다.

- 작업방법 변경
- 작업자 또는 작업팀 변경
- 작업장소 변경
- 설비·장비·공구 변경
- 사용물질 변경
- 에너지원 변경
- 신규 위험요인 발견
- 작업중지 후 재개
- 허가조건 변경
- 장시간 작업중단 후 재개
- 현장 안전조치 훼손 또는 변경

### 50.4 고위험작업 강화 점검

고위험작업은 3시간 이내 기본 이행상태 확인에 더해 다음 강화 점검을 적용한다.

| 점검 주체 | 점검 주기 |
|---|---|
| 생명지킴이 | 2시간마다 |
| 정비부서 담당자 | 오전·오후 각 1회 |
| 운영부서 관리감독자 | 오전·오후 각 1회 |
| 안전환경부서 | 오전·오후 각 1회 |

고위험작업의 강화 점검이 모든 허가작업에 적용되는 3시간 이내 기본 확인을 자동으로 대체하지 않는다.

같은 시간대에 동일한 권한과 확인범위를 가진 점검으로 중복 인정할 수 있는지는 사내 운영기준에 따라 결정하고, 중복 인정 시 근거를 기록한다.

### 50.5 밀폐공간 측정과의 구분

밀폐공간 작업 중 1시간마다 실시하는 산소·유해가스 측정은 작업 중 안전 이행상태 점검과 별개의 기록이다.

- 3시간 이내 이행상태 확인: 허가조건과 안전대책 전반 확인
- 1시간마다 가스 측정: 산소·유해가스 농도 확인
- 고위험 주기점검: 작업유형별 안전조치 유지 여부 확인

가스 측정만 실시했다는 이유로 일반 이행상태 확인을 생략하지 않는다.

### 50.6 미흡사항 처리

점검 결과 필수 안전조치 미이행 또는 중대한 위험이 발견되면 다음 순서로 처리한다.

1. 즉시 작업중지 또는 위험구역 통제
2. 미흡사항 기록
3. 개선조치 담당자 지정
4. 개선조치 실시
5. 재점검
6. 필요한 경우 위험성평가 재검토
7. 허가 재확인 또는 재허가
8. 재TBM
9. 권한 있는 사람의 작업 재개 승인

최초 미흡 판정은 삭제하거나 양호로 덮어쓰지 않는다.

- 재가동 승인 필요 상태
- 관련 점검기록 미완료

### 29.5 종료 보조 상태

- 건강상태

다음 원칙을 적용한다.

- 공개 저장소에 실제 개인정보 저장 금지
- 문서별 접근권한 제한
- 리포트에서 불필요한 개인정보 제외
- 보존기간과 삭제정책 설정
- 건강정보를 협력사 평가에 사용하지 않음
- 위험 신고 권리를 개인정보 제공 여부로 제한하지 않음

### 31.3 사진과 첨부자료

점검사진·서명·첨부파일을 Firestore 본문에 큰 Base64 값으로 저장하지 않는다.

첨부파일 저장정책이 확정되기 전에는 다음을 관리한다.

- 첨부자료 존재 여부
- 파일명
- 자료 유형
- 참조 경로
- 업로드자
- 업로드 시각
- 개인정보 포함 여부
- 공개 가능 여부

## 37. 완료 기준

종이 서식 전자화는 다음 조건을 모두 충족할 때 완료로 판단한다.

- 종이 서식의 필수항목이 전자 필드에 매핑됨
- 작성자·확인자·승인자 역할이 구분됨
- 안전정보제공서 도급·수급 흐름이 연결됨
- 안전퀴즈 합격이 작업 참여 조건으로 적용됨
- 위험성평가가 위험요인별로 수행됨
- 고위험작업 판정과 사전승인이 관리됨
- 허가 전 ILS 완료상태가 확인됨
- 밀폐공간 측정이 위치·시간별로 기록됨
- TBM에 위험·대책·조치자가 연결됨
- 작업중지권 고지와 실제 요청이 분리됨
- 작업 중 점검과 미흡조치가 기록됨
- 변경 시 재평가·재허가·재TBM이 연결됨
- 작업 종료 시 철수·복구가 확인됨
- ILS 해제 완료 전 최종 작업완료가 제한됨
- permitNo 기준 통합 리포트가 가능함
- 감사 필드와 상태 변경 이력이 유지됨
- 개인정보와 건강정보의 접근이 제한됨

## 39. 최종 원칙

전자 안전관리 플랫폼은 다음 업무 흐름을 일관되게 지원해야 한다.

> 안전정보 제공 → 안전퀴즈 합격 → 위험성평가 → 고위험 사전승인 → 안전작업허가 → ILS 완료 확인 → TBM → 작업 중 점검 → 필요 시 작업중지 → 조치·재평가·재TBM → 작업 종료 → ILS 해제 확인 → 설비 인계 → 통합 보관

각 문서는 독립적으로 저장하되 workId, permitNo, riskId, tbmNo, emergencyNo 및 jsaId로 연결한다.

동일한 정보는 반복 입력하지 않고 원본 문서를 조회한다.

AI와 JSA_DB는 위험요인과 안전대책을 제안하고 누락을 점검하는 보조수단으로 사용한다.

최종 위험성평가, 작업허가, 작업중지 후 재개 및 작업완료는 권한 있는 사람이 현장조건을 확인한 후 확정한다.
